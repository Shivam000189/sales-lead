# Phase 2: Plan 01 - Outbound Email Integration & Activity Logging

## Goal
Implement outbound emailing to leads directly from the CRM Lead Detail view with branded HTML templates, role-based ownership authorization, Zod validation, error resilience, and automated timeline activity tracking.

---

## Tasks

### Task 1: Install `nodemailer` and Configure SMTP Environment
- **Files**: `server/package.json`, `server/.env.example`
- **Action**:
  - Install `nodemailer` in `server/`.
  - Add SMTP variables (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`) to `server/.env.example`.
- **Verification**: `npm --prefix server list nodemailer` confirms installation.

---

### Task 2: Build HTML Email Template Utility
- **File**: `server/src/utils/emailTemplates.js` (NEW)
- **Action**:
  - Implement `buildLeadEmailHtml({ subject, message, leadName })`.
  - Format HTML with branded header ("HeroCRM"), greeting, message body, signature, and footer.
- **Verification**: Unit call returns valid, well-structured HTML string.

---

### Task 3: Implement Email Dispatch Service
- **File**: `server/src/services/emailService.js` (NEW)
- **Action**:
  - Create transport pool using nodemailer with environment variables.
  - Implement `sendEmail({ to, subject, html, text })`.
  - Handle missing SMTP configuration gracefully in dev mode (log test preview instead of crashing).
  - Throw clear error on transmission failure.
- **Verification**: Calling `sendEmail` in dev environment logs preview without crashing server.

---

### Task 4: Add Email Input Validation Schema
- **File**: `server/src/validations/emailValidation.js` (NEW)
- **Action**:
  - Define `sendEmailSchema` using Zod:
    - `subject`: string, min 1, max 150.
    - `message`: string, min 1, max 5000.
- **Verification**: Invalid subject or empty message triggers 400 validation error.

---

### Task 5: Implement Email Controller & Route
- **Files**:
  - `server/src/controllers/emailController.js` (NEW)
  - `server/src/routes/leadRoutes.js`
- **Action**:
  - `sendLeadEmail`:
    - Fetch lead by `:id` (404 if not found).
    - Enforce ownership: if user is member, verify `lead.assignedTo?.toString() === req.user.id` (403 if unassigned or owned by another member).
    - Generate HTML using `buildLeadEmailHtml`.
    - Call `emailService.sendEmail`.
    - On success: call `createActivity(lead._id, `Email sent: ${subject}`, req.user.id, "EMAIL_SENT")`.
    - Return 200 `{ success: true, message: "Email sent successfully", data: activity }`.
    - On failure: return 502/400 without creating an Activity.
  - In `leadRoutes.js`:
    - Add `POST /:id/send-email` with `authenticate` and `validate(sendEmailSchema)`.
- **Verification**: Route exists and enforces auth, validation, and ownership.

---

### Task 6: Frontend Send Email Modal & Timeline Integration
- **Files**:
  - `client/src/pages/CrmPages.jsx`
  - `client/src/App.css`
- **Action**:
  - In `LeadDetails`:
    - Add state for `emailModalOpen`, `emailForm` (`subject`, `message`), `sendingEmail`, `emailSuccess`.
    - Render "Send email" action button.
    - Render modal dialog with Subject, Message, recipient indicator, and Cancel/Submit buttons.
    - On submit: call `API.post(`/leads/${id}/send-email`, emailForm)`.
    - On success: close modal, show success toast, prepend new activity to `activities` state without full page reload.
    - On failure: display error toast.
    - In timeline renderer: render distinct mail badge (✉ / icon) when `a.type === "EMAIL_SENT"`.
  - In `App.css`:
    - Add styling for modal overlay, modal card, form inputs, and timeline email badge.
- **Verification**: Clicking "Send email" opens modal, submitting triggers request, success closes modal and prepends timeline item.

---

## Verification Checklist
- [ ] `nodemailer` installed in `server/package.json`.
- [ ] `POST /api/leads/:id/send-email` rejects unauthenticated requests with 401.
